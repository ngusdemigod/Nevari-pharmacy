# Corrected Medication Therapy Management System Flow

## Important Role Correction

Doctors should not be treated as pharmacists in the MTM system.

On plugin activation, the WordPress plugin must create a new user role called:

```text
pharmacist
```

The `pharmacist` role should be separate from the doctor role. MTM review, appointment scheduling, MTM consultation, Medication Action Plan creation, follow-up scheduling, and outcome tracking should be handled by users with the `pharmacist` role.

Doctors should keep their own existing role and permissions, but doctors should not automatically receive MTM pharmacist permissions unless the admin separately assigns them the `pharmacist` role.

# Main MTM Statuses

These statuses should be shared across the customer dashboard, pharmacist dashboard, and admin dashboard.

```text
Submitted
Under Review
Appointment Scheduled
Consultation Completed
Medication Action Plan Created
Follow-Up Scheduled
Outcome Tracking
Completed
```

## Status Meaning

| Status       | Meaning                                                        |
| ------------ | -------------------------------------------------------------- |
| Submitted    | Patient has completed and submitted the MTM form.              |
| Under Review | A pharmacist is reviewing the submitted MTM form.              |
| Scheduled    | The pharmacist has scheduled the MTM consultation appointment. |
| Completed    | The MTM consultation with the pharmacist has been completed.   |
| Approved     | the MTM request has been approved after being under review     |
| Follow-Up    | A follow-up appointment has been scheduled by the pharmacist.  |
|              |                                                                |

# 1. Patient Completes MTM Form

The patient must have an active paid subscription that includes MTM access.

Before showing the MTM form, the backend must verify:

```text
Patient is logged in
Patient has an active subscription
Patient plan includes MTM access
Patient is allowed to submit an MTM request
```

The patient completes the MTM form, including:

```text
Patient details
Emergency contact information
Medical and clinical history
Medication profile
Medication adherence assessment
Additional medication information
Review and submit
```

The form is submitted to the backend:

```http
POST /wp-json/nevari/v1/mtm-requests
```

After submission, the MTM request status becomes:

```text
Submitted
```

---

# 2. Automatic Thank You Message

Immediately after submission, the patient should see this message:

```text
Thank you for completing the MTM Patient Assessment Form.

Your information has been received. A NevariHealth pharmacist will review your submission and contact you regarding your MTM consultation.
```

The system may also send email and WhatsApp notifications, but the message must not expose sensitive medical details.

---

# 3. MTM Request Is Assigned to a Pharmacist

After submission, the backend automatically assigns the MTM request to an available pharmacist.

The assignment logic should check:

```text
User has pharmacist role
Pharmacist account is active
Pharmacist is available
Pharmacist is allowed to manage MTM requests
Pharmacist has the lowest active MTM workload
Pharmacist is not suspended
```

The request should store:

```text
assigned_pharmacist_id
reviewed_by_pharmacist_id
assigned_at
status
```

The status changes to:

```text
Under Review
```

The assigned pharmacist receives a notification:

```text
A new MTM request has been assigned to you.

Please log in to your pharmacist dashboard to review the request.
```

---

# 4. Pharmacist Reviews Form

On the pharmacist dashboard, the pharmacist should see a list of assigned MTM requests.

Example:

```text
MTM Requests

Patient Name | Status | Submitted Date | Action
John Doe     | Under Review | June 5, 2026 | Open
```

When the pharmacist opens the request, the dashboard loads the MTM details:

```http
GET /wp-json/nevari/v1/pharmacist/mtm-requests/{mtm_request_id}
```

The pharmacist reviews:

```text
Patient bio data
Emergency contact
Vital signs
Medical conditions
Medication history
Current medications
Allergies
Adherence barriers
Lab results
OTC medications
Supplements
Herbal products
Other submitted notes
```

After reviewing the form, the pharmacist can proceed to schedule the MTM consultation.

# 5. Appointment Scheduled by the Pharmacist

The appointment should be scheduled by the pharmacist, not by the patient.

On the pharmacist dashboard, there should be a button:

```text
Schedule MTM Appointment
```

When the pharmacist clicks this button, the system should allow the pharmacist to select:

```text
Appointment date
Appointment time
Appointment duration
Consultation method
Optional appointment note
```

Example payload:

```json
{
  "appointment_start": "2026-06-10T14:00:00",
  "appointment_end": "2026-06-10T14:30:00",
  "timezone": "Africa/Lagos",
  "consultation_method": "Video Call",
  "note": "Please be available with your current medications."
}
```

Endpoint:

```http
POST /wp-json/nevari/v1/pharmacist/mtm-requests/{mtm_request_id}/schedule
```

The backend must verify:

```text
Pharmacist is authenticated
Pharmacist has pharmacist role
Pharmacist is assigned to the MTM request
Patient owns the MTM request
Patient has active MTM subscription access
Selected appointment slot is available
No extra MTM consultation payment is required
```

After scheduling, the MTM request status becomes:

```text
Appointment Scheduled
```

The patient receives confirmation by email and dashboard notification.

Example:

```text
Your MTM consultation has been scheduled.

Pharmacist: [Pharmacist Name]
Date: [Date]
Time: [Time]
Duration: 30 minutes

Please log in to your NevariHealth dashboard to view your appointment details.
```

# 6. MTM Consultation with Pharmacist

At the scheduled time, the pharmacist conducts the MTM consultation with the patient.

The pharmacist dashboard should allow the pharmacist to document:

```text
Consultation notes
Add products on the woocommerce store to the MTM request and then it displays as an unpaid order linked to the MTM request on the customers dashboard
```

After the consultation is completed, the pharmacist can mark the consultation as completed.

The status becomes:

```text
Completed
```

---

# 7. Medication Action Plan Generated by the Pharmacist

After the consultation, the pharmacist generates the Medication Action Plan from the pharmacist dashboard.

On the pharmacist dashboard, there must be a clear button:

```text
Add Medication Action Plan
```

When the pharmacist clicks this button, the system should open a Medication Action Plan form.

The Medication Action Plan may include:

```text
Summary of consultation
Medication concerns identified
Recommended medication actions
Instructions for the patient
Adherence recommendations
Lifestyle advice
Follow-up recommendation
Recommended pharmacy products
Pharmacist notes
```

The pharmacist should also have a button:

```text
Attach Pharmacy Products
```

This allows the pharmacist to attach products or drugs from the pharmacy catalog.(this should be a search to add field)

The pharmacist can select:

```text
Product name
Quantity
Dosage instruction
Usage note
Refill instruction
```

Endpoint:

```http
POST /wp-json/nevari/v1/pharmacist/mtm-requests/{mtm_request_id}/action-plan
```

After the Medication Action Plan is submitted, the status becomes:

```text
Medication Action Plan Created
```

---

# 8. Product Order from Medication Action Plan

If the pharmacist attaches pharmacy products to the Medication Action Plan, the backend should create a real customer product order.

The order source should be:

```text
MTM Medication Action Plan
```

The order should store:

```text
customer_id
mtm_request_id
pharmacist_id
medication_action_plan_id
order_items
order_status
payment_status
created_at
```

Recommended order status:

```text
Pending Payment
```

The MTM consultation is included in the patient’s subscription, but the attached drugs or pharmacy products require payment if the patient decides to purchase them.

The patient should see the recommended products inside the Medication Action Plan with a button:

```text
View Order
```

The button should link to:

```text
/customer-dashboard/orders/{order_id}
```

or:

```text
/dashboard/orders/{order_id}
```

If the pharmacist determines that the patient needs further monitoring, the pharmacist can schedule a follow-up appointment.

On the pharmacist dashboard, there should be a button:

```text
Schedule Follow-Up Appointment
```

The pharmacist selects:

```text
Follow-up date
Follow-up time
Follow-up purpose
Follow-up note
```

Endpoint:

```http
POST /wp-json/nevari/v1/pharmacist/mtm-requests/{mtm_request_id}/follow-up-schedule
```

After scheduling the follow-up, the status becomes:

```text
Follow-Up Scheduled
```

The patient receives a notification:

```text
A follow-up MTM appointment has been scheduled.

Pharmacist: [Pharmacist Name]
Date: [Date]
Time: [Time]

Please log in to your dashboard to view the appointment details.
```

# 10. Outcome Tracking

After the Medication Action Plan and follow-up appointment, the pharmacist should be able to track patient outcomes.

On the pharmacist dashboard, there should be an outcome tracking section. this should be a tab on the Request details and also a standalone page that lists all mtm requests and when clicked leads directly to that tab on the details page

The pharmacist can record:

```text
Medication adherence progress
Patient response to treatment
Side effects reported
Medication changes
Clinical improvement
Follow-up outcome
Pharmacist recommendation
Final notes
```

Endpoint:

```http
POST /wp-json/nevari/v1/pharmacist/mtm-requests/{mtm_request_id}/outcome-tracking
```

The status becomes:

```text
Outcome Tracking
```

---

# 11. Case Completed

When no further action is required, the pharmacist or admin can close the MTM case.

The final status becomes:

```text
Completed
```

The patient can still view:

```text
Submitted MTM form
Appointment details
Medication Action Plan
Linked product order
Follow-up history
Outcome tracking summary
```

But the MTM case is no longer active.

# Security Rules

The backend plugin must remain the trusted authority.

The frontend must never decide:

```text
Whether the patient has MTM access
Which pharmacist is assigned
Whether a pharmacist can review an MTM request
Whether a pharmacist can schedule an appointment
Whether a Medication Action Plan belongs to the patient
Whether an order belongs to the patient
Whether product prices are valid
Whether a product order should be created
```

The backend must validate every action.

## Required Checks

For MTM submission:

```text
Patient is authenticated
Patient has active subscription
Subscription includes MTM
Form data is validated and sanitized
```

For pharmacist access:

```text
User is authenticated
User has pharmacist role
Pharmacist is active
Pharmacist is assigned to the MTM request
Admin can override if needed
```

For appointment scheduling:

```text
Only assigned pharmacist or admin can schedule
Patient owns the MTM request
Patient has active MTM access
Appointment slot is available
No extra MTM consultation payment is required
```

For Medication Action Plan:

```text
Only assigned pharmacist or admin can create it
Medication Action Plan must be linked to the MTM request
Products must exist in the pharmacy catalog
Product prices must come from the backend
Customer order must be created server-side
```

For outcome tracking:

```text
Only assigned pharmacist or admin can update outcome tracking
Outcome notes must be linked to the MTM request
Patient can view outcome summary but cannot edit pharmacist records
```

On plugin activation, create the pharmacist role:

```text
Role slug: pharmacist
Role name: Pharmacist
```

Recommended pharmacist capabilities:

```text
read
nevari_view_mtm_requests
nevari_review_mtm_requests
nevari_schedule_mtm_appointments
nevari_create_medication_action_plan
nevari_attach_pharmacy_products
nevari_create_mtm_product_order
nevari_schedule_follow_up
nevari_track_mtm_outcomes
nevari_complete_mtm_case
```

Only users with the `pharmacist` role or admin privileges should perform pharmacist MTM actions.
